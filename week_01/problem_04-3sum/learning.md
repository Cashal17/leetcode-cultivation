## Takeaways:

Brute-forcing this problem would be really easy, where we would run an outer loop for each element, then an inner loop for each pair of elements, and another nested inner loop for each triplet of elements. This would have a time complexity of O(N^3) though.

The main idea to understand behind this problem is that we want to run an outer loop where we fix the ith value and then run a 2sum check with -nums[i] as the target (since i + j + k = 0 can be expressed as i + j = -k). First we have to sort the array since we can then break the inner two-pointer loop comparison into 3 cases: (1) sum is greater than 0 so we can move the right pointer at the larger value to a smaller one (2) sum is less than 0 so we can move left pointer at the smaller value to a greater one (3) sum is equal to 0 so we have found a valid triplet and need to make sure it doesn't duplicate. The sorted array makes sure we actually iterate/converge towards a sum of 0 instead of just brute-force checking random combinations. This way, via sorting + two-pointers, we get a time complexity of O(N^2) since the sorting is O(nlogn) and is dominated by the outer + inner loop's overall complexity.
