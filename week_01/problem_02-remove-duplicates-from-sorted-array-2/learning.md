## Takeaways:

For this problem, first think about just removing all duplicates for a given list. The basic logic behind maintaining a count index and only setting/updating the count index if the following number is not a duplicate, meaning we are only copying down the last number from a series of duplicates, is simple. Even when dealing with at most one duplicate allowed, simply using a hashmap to keep track of each duplicates number's frequency and only setting/updating the count index if the frequency is not more than 2, meaning we are only copying down the first and last numbers in a series of duplicates for ultimately no more than one duplicate per unique value, gets a working solution with time complexity of O(N).\
However, we can optimize this space complexity further from O(M) with the frequency map where M = # of unique values. Since we notice our frequency map only has two states, freq = 2 or freq = 3, we can reduce this data structure away and just use pointers to get to a space complexity of O(1). We have our count pointer start at index 2, and we compare value at current index to the value 2 behind the count pointer (which is our updated list rather than our old one which could skip single duplicates due to overlap between input list and output list). This way, if the value two spaces behind the count pointer of the new list is still the same as the current, then the current is showing up too many times and we "delete" the value of the current index by skipping its iteration.
