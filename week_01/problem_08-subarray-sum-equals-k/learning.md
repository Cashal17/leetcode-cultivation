## Takeaways:

We could brute-force this by simply using an outer loop that iterates over each element in the list and a nested inner loop that checks every subarray in the list that starts with the outer loop's iterated element. We update currentSum as we check each subarray and currentSum equals k, we update count. This is still a poor time complexity of O(N^2) due to the nested loop.

We can optimize this further by using prefix sums. The prefix sums will be an array of length N and each prefixSum[i] = sum of an array's elements from arr[0]...arr[i], so prefixSum[i+1] = prefixSum[i] + arr[i+1]. We iterate over nums and update our prefixSum by the element, storing each sum->freq. entry in a hashmap. We start with {0: 1} meaning for a sum of 0 we have one subarray (an empty one). In a future element iteration, if the updated prefixSum and k (sum we are looking for) have a difference that has already been stored in the hashmap, then that means that hashmap key is another continguous value that adds up to k and its hashmap value is the # of unique subarrays possible with that key value and sum equal to k so we can simply add that hashmap value to our answer. By the end of our O(N) linear main loop, we should have made all additions to our final answer by adding the # of unique subarrays for every key value together, so we should have accounted for every single possible continguous subarray adding up to k.
